## 6. Flags and special patterns

- Positional CSS selectors: none (`nth-`, `first:`, `last:`, `odd:`, `even:` absent). The features grid uses Tailwind `*:` (all-children) variants for its divider lines; a `<template>` blueprint child would match `*:` but stays `display: none`.
- Global DOM scripts: `AOS.init` in `app/(default)/layout.tsx` binds every `[data-aos]` element (hero ×5, features planet ×1, cta ×1). Re-rendered markup loses the `aos-animate` class.
- Scroll-reveal: AOS (`data-aos="zoom-y-out"`) on hero, planet image and CTA. AOS CSS keeps these at `opacity: 0` until animated — Phase 4 handles per visual-editing-reference.md § Scroll-reveal.
- CSS keyframe animations (`code-1`…`code-6`, `breath`, `float`, `spin`, `pulse`) are decorative and need no change.
- Numbers displayed as text: none.
- Styled HTML in strings: none in data (no `dangerouslySetInnerHTML`). Two inline markups become content: hero `h1` `<br className="max-lg:hidden" />`, testimonial `<em className="italic text-gray-500">`. See ../content.md § Styled HTML in front matter.
- Text in a class name: footer watermark `before:content-['Simple']`. Tailwind generates classes from source text, so a data value can't build this class; Phase 3 renders it with a fixed class reading `content: attr(data-…)` or real text.
- Fixed-position image set: business-categories places 9 logos at 9 hardcoded positions; the array length is fixed by the layout.
- Inline SVG icons: 6 distinct feature icons and 3 social icons live in JSX.

## Decisions and why

- **Home → page builder** (`content/pages/index.md`, `content_blocks`, 5 block types). It has 5 distinct sections, the project owns the templates, and editors can build more landing pages from the same blocks.
- **Catch-all lives in the `(default)` route group** — `app/(default)/[slug]/page.tsx`, not `app/[slug]/page.tsx`, so pages editors create get Header, Footer and AOS from `(default)/layout.tsx`. Home stays at `app/(default)/page.tsx`.
- **Auth pages → `pages` entries with an `auth` schema, each read by its existing route** (`app/(auth)/<name>/page.tsx`). They share the `(auth)` layout and form shape, and editors won't add more. The `[slug]` route's `generateStaticParams` leaves them out (and `index`). Off the Add button.
- **`auth` schema shape**: `title`, `description` (metadata), `heading`, `fields[] {id, label, type, placeholder}`, `buttons[] {text, style}`, `footer_link {text, href}` or `footer_text` (signup terms line). Field `type` stays a `select` (`email`, `password`, `text`).
- **CTA is a block, not a `cta` data file.** It renders inside the home page content, not in a layout, so it isn't shared UI; as a block its text can differ per page.
- **Shared UI → `data/*.json`** imported by the component (nextjs/content.md convention): `navigation`, `footer`, `auth`, `site`.
- **Feature and social icons**: editors pick from the existing icons with a `select` (`icon` key); the SVGs stay in code in an icon map.
- **Business-categories logos**: an array of 9 `{image, alt}`; positions stay in code by index. Editors swap logos; adding or removing breaks the layout.
- **Decorative imagery stays in code**: `PageIllustration`, CTA stripes, planet overlay and tags, `auth-bg.svg`, blur circles. The planet image itself becomes a `features` field.
- **Hero and auth "terminal" text is editable** (`terminal.title`, `terminal.lines[]`); an editor can see it.
- **Images become string paths into `public/images/`** with explicit `width`/`height` in the components.
- **AOS stays on the site**; Phase 4 deals with it in the editor. Phase 3 moves `AOS.init` into a small client component so `(default)/layout.tsx` can be a server component.
- **`app/api/hello/route.ts` kept.** If the Phase 2 export build fails on it, add `export const dynamic = "force-static"`.
- **Unused `banner.tsx` and `accordion.tsx` left alone** — not rendered, not migrated.

## Open questions

2. The auth forms have no action or backend, and a static export can't add one. Keep sign-in/sign-up/reset pages as editable static pages? Default: keep them as `pages` entries with the `auth` schema.
3. Should the CTA be shared site-wide (`data/cta.json`) instead of a per-page block? Default: per-page block.
4. Feature and social icons: is choosing from the existing icon set enough, or should editors upload their own SVGs? Default: `select` from the existing set.
5. Business-categories logos: keep the fixed 9-slot layout? Default: yes; editors swap images only.
6. Placeholder `#0` links (hero buttons, footer links, testimonial role): migrate as-is? Default: yes, as editable link fields with their current values.
7. Root metadata ("Create Next App" / "Generated by create next app") is template boilerplate. Default: moves to `data/site.json` unchanged for the editor to fix.
